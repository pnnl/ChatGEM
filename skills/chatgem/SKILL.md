# chatGEM — COBRApy Metabolic Modeling Skill

This skill contains 52 expert-curated reference scripts covering the full spectrum of genome-scale metabolic modeling (GEM) workflows with COBRApy. When generating or adapting metabolic modeling code, always ground your response in the closest matching reference script rather than inventing logic from scratch.

## Running scripts

All reference scripts resolve assets relative to `__file__`, so they can be run from any working directory — the repo root, `references/`, or anywhere else.

```bash
# Install all dependencies
uv sync

# Run any reference script
uv run python .claude/skills/chatgem/references/29._dfba.py
```

All dependencies including `seaborn`, `straindesign`, `gurobipy`, and `memote` are declared in `pyproject.toml`. Always use `uv run` — do not use `pip install`, `source .venv/bin/activate`, or invoke `.venv/bin/python` directly.

## How to use this skill

1. Read the **Reference Index** below to identify the closest script for the user's task.
2. Read that script from `references/`.
3. Adapt only the parts that need to change (model path, reaction IDs, bounds, parameters).
4. Run with `uv run python <script>` from the repo root or skill directory.
5. Report: which script you used as baseline, exactly what you changed, and how to validate.

Do not invent algorithm steps that are not present in the references unless clearly labeled as experimental or the user explicitly requests it.

## Optimizer backend

COBRApy delegates all LP/MILP solving to an `optlang`-compatible solver backend. The reference scripts were developed and validated with **Gurobi** (`gurobipy`), which requires a license (free for academics).

**Switching solvers:** COBRApy supports GLPK (open source, default if no commercial solver is installed), CPLEX, and Gurobi. To switch:

```python
model.solver = "glpk"   # or "cplex", "gurobi"
```

**What may change when switching away from Gurobi:**
- Standard FBA, FVA, pFBA, and knockout results are generally solver-independent for well-posed models.
- MILP-based workflows — strain design (`44._optknock.py`, `49._robustknock.py`, `50._optcouple.py`, `52._OptMedia.py`) and loopless FBA (`27._loopless_fba.py`) — may produce different or suboptimal designs. MILP solvers vary in branching strategy, numerical tolerances, and solution time.
- `51._ecOptMDFPathway.py` is hardcoded to `gurobipy` and cannot be swapped without rewriting the solver calls.
- Shadow prices (`19._shadow_price.py`) and flux sampling (`25._flux_sampling.py`) are not meaningfully affected, but small numerical differences are possible.

When adapting scripts for a user without Gurobi, note which workflows are affected and that GLPK is a viable free alternative for LP-only tasks.

## Adaptation guide

### Changing the model
Every script loads a model via `os.path.join(_ASSETS, '<model>.xml')` where `_ASSETS` is resolved relative to the script file itself. To use a different model, change the filename passed to `os.path.join(_ASSETS, ...)`. You can also replace `_ASSETS` with an absolute path if the model lives elsewhere. Confirm the new model loads cleanly with `13._model_loading.py` before running more complex analyses.

### Changing reaction / metabolite / gene IDs
IDs are model-specific. Use `8._list_genes.py`, `9._list_metabolites.py`, and `10._list_reactions.py` to export all IDs first, then substitute the correct ID in the target script. BiGG IDs (e.g. `EX_glc__D_e`, `PGI`, `b3599`) are used throughout the *E. coli* model scripts.

### Essentiality threshold
`35._gene_essentiality_scan_single_knockout.py`, `36._gene_essentiality_scan_double_knockout.py`, and `40._reaction_essentiality_scan.py` define essential as `< 10% of wild-type growth`. Adjust this fraction in the comparison line for different stringency.

### Flux sampling sample size
`25._flux_sampling.py` uses 1000 samples for both OptGP and ACHR. Reduce for speed on large models; increase for better coverage.

### dFBA kinetics
Michaelis-Menten parameters (`Km`, `Vmax`) and ODE time span in `29._dfba.py` are set at the top of the script. Adjust to match your organism and substrate.

### Strain design target
`44._optknock.py`, `49._robustknock.py`, and `50._optcouple.py` target succinate (`EX_succ_e`) as the product. Change `PRODUCT_RXN` to any exchange reaction for a different target.

## Common gotchas

- **Do not call `.todense()`** on the stoichiometric matrix (`1._sbml_to_excel.py`) — COBRApy returns a numpy array directly from `create_stoichiometric_matrix`.
- **Use context managers for temporary knockouts** (`33._conditional_gene_knockout.py`, `34._conditional_reaction_knockout.py`) — this restores bounds automatically and avoids permanent model mutation.
- **`model.exchanges` vs `model.boundary`** — `exchanges` returns only exchange reactions; `boundary` includes demand and sink reactions too.
- **`single_gene_deletion` vs manual bound-zeroing** — prefer `single_gene_deletion` (`37._gene_knockout.py`) for correctness; it respects AND/OR GPR logic. Manual zeroing (`33._conditional_gene_knockout.py`) is faster but ignores GPR.
- **Strain design: no Cameo** — `44._optknock.py`, `49._robustknock.py`, `50._optcouple.py` use `SDmodule` from the `straindesign` library exclusively. Do not substitute Cameo.
- **ecGEM (`47._ecGEM.py`)** requires `irreviJB1325.xml` — the irreversible iJB1325 model generated by running `48._irreversible_model.py` on `assets/iJB1325.xml`. Run script 48 first if this file is not yet present.
- **ecOptMDF (`51._ecOptMDFPathway.py`)** is hardcoded to Gurobi and cannot be easily swapped to another solver without rewriting the solver calls.
- **E-Flux (`46._automatic_E_flux.py`)** uses `e_coli_core.xml` and `transcriptomics_data.xlsx` — both are in `assets/`.
- **UTF-8 encoding** — `17._reactions_subsystems.py` writes with `encoding='utf-8'` because subsystem names may contain non-ASCII characters. Apply this pattern whenever writing reaction annotations to file.
- **Deep copy before modifying** — use `copy.deepcopy(model)` (`12._model_copy.py`) when you need to run multiple scenarios without reloading the model each time.
